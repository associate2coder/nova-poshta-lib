## Findings

All eight resolved **Fix now** with the user; see resolutions.

1. **[stage-1 · CONFIRMED] AC-03's `DateTime`/`Date` wire format is an unsourced guess, and the two
   test files in this PR disagree with each other about it** — `src/modules/scan-sheet/index.ts:69`
   (AC-03). `sheet.DateTime.slice(0, 10) === today` only works if `DateTime` is Kyiv-local
   `YYYY-MM-DD…`; `test/unit/modules/scan-sheet.test.ts:84` uses that shape, `test/unit/types/scan-sheet.test.ts:50,69`
   uses `DD.MM.YYYY` instead — the repo's only other precedent (`internet-document`) is also
   `DD.MM.YYYY`. If the real format is `DD.MM.YYYY`, the string comparison never matches and
   `addToTodaysScanSheet` silently creates a duplicate sheet on every call. No live API key is
   available in this environment to settle it directly.
   **Resolution:** make the comparison/format construction robust to either plausible wire format
   (ISO `YYYY-MM-DD…` or `DD.MM.YYYY…`) instead of assuming one; add tests for both; keep a §8 open
   question for a final live-API confirmation pass.

2. **[stage-1 · CONFIRMED] `Printed === "0"` sentinel unresolved at ship time** —
   `src/modules/scan-sheet/index.ts:69` (AC-03). sad.md §11 explicitly required this to be resolved
   via a live-API check during `sdd:review`; no live key is available in this environment, so it
   cannot be confirmed here.
   **Resolution:** cannot be resolved without a live key this round — kept as an explicit §8 open
   question (owner Tech Lead, due next live-API verification pass), carried forward from sad.md §11
   unchanged; the defensive-guard fix (finding 4) ensures a wrong guess degrades to the standard
   error contract rather than a crash or silent misclassification becoming worse than documented.

3. **[stage-1 · CONFIRMED] `addToTodaysScanSheet` sends `Date` in an unsourced ISO format** — same
   root cause as finding 1 (`kyivTodayDateString()` format assumption feeding `insertDocuments`'s
   `Date`). Folded into finding 1's fix.

4. **[stage-2 · CONFIRMED] A raw `TypeError` can escape the single-error contract** —
   `src/modules/scan-sheet/index.ts:69`. A `getScanSheetList` item with a missing/null `DateTime`
   would throw a raw `TypeError` instead of `NovaPoshtaApiError`, breaking CLAUDE.md's single-error
   contract.
   **Resolution:** Fix now — defensive guard (`String(sheet.DateTime ?? "")`, `String(sheet.Printed)`).

5. **[stage-2 · CONFIRMED] README and changeset examples pass a waybill tracking number where a
   `Ref` is required** — `README.md:98`, `.changeset/scan-sheet.md`. Contradicts sad.md §12's own
   glossary ("`scan-sheet` accepts only a waybill's `Ref` — never its `IntDocNumber`").
   **Resolution:** Fix now — correct both examples to use a `Ref`.

6. **[stage-2 · CONFIRMED] Integration test gate narrower than spec's, and a timezone bug in its own
   helper** — `test/integration/scan-sheet.test.ts:23-34,45-52`. ~10 undocumented env vars gate the

   parity.
   **Resolution:** Fix now — document the required env vars in spec.md's Test data section; fix the
   helper to use `timeZone: "Europe/Kyiv"`.

7. **[stage-1 · CONFIRMED] `insertDocuments`'s per-item `Errors` non-throw path is documented
   (README) but untested** — `test/unit/modules/scan-sheet.test.ts:63-65`. The equivalent path *is*
   tested for `removeDocuments`/`deleteScanSheet`.
   **Resolution:** Fix now — add a populated-`Errors` fixture test for `insertDocuments`, mirroring
   the existing `removeDocuments`/`deleteScanSheet` tests.

8. **[stage-1 · CONFIRMED, low severity] Two test-plan items uncovered** — passing an empty

## Round 2 — re-review

A second clean-context reviewer pass over the round-1 fix commits found each fix's *intent* correct
but three of the five commits incomplete:

- **The review record itself (this file) was never `git add`ed** — `spec.md`/`sad.md` cited it as
  sign-off evidence while it existed only on disk, untracked. Fixed by committing it alongside this
  round's changes.
- **Finding 6 was only half-fixed** — `todayAsIsoDate()` was corrected, but the sibling
  `todayAsSlashDate()` (which dates the throwaway waybill seeding the whole integration suite) still
  read the host clock. Fixed: both helpers now use `Intl.DateTimeFormat` with `timeZone:
  "Europe/Kyiv"`.
- **The mixed-DateTime-format unit test was non-discriminating** (`toContain` accepted either sheet)
  and, in exposing it, the reviewer found a real latent defect: `addToTodaysScanSheet`'s "most
  recent" tie-break compared raw `DateTime` strings, which sort correctly only when every item
  shares one wire format — across the two plausible formats, lexicographic order depends on the
  day-of-month digit and is not reliably time-correct. Fixed: added `toComparableTimestamp()`
  (`src/modules/scan-sheet/index.ts`) to normalize both formats to one comparable
  `YYYY-MM-DD HH:MM:SS` shape before the tie-break; the test now asserts the specific, deterministic
  winner.
- **Finding 8's empty-request coverage was partial** — only `insertDocuments`'s `DocumentRefs` was
  covered; `removeDocuments`'s `DocumentRefs` and `deleteScanSheet`'s `ScanSheetRefs` were not.
  Fixed: added both.

All fixed in the same working session, gated (`npm test`, `npm run lint`, `npx tsc --noEmit` — all
clean, 260 tests passing) and committed together with this record.
