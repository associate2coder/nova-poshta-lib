## Findings

All five resolved **Fix now** with the user.

1. **[stage-1 · CONFIRMED] No upstream struct/schema is quoted anywhere in this feature's
   artifacts** — `spec.md:12,68,87` and `contracts/public-api.md:477` cite SDKs and struct names
   (`platx`'s `SaveChangeEWReq`, `sirkostya009`'s `ChangeEWRequest`) *by name only*;
   `contracts/api-sync-report.md:17-63`'s entire `Origin` column is self-referential (`spec §1 row
   N` — a generated artifact citing a generated artifact). CLAUDE.md's API-contract sourcing
   policy requires "quote or list the exact upstream struct/schema used for the decision, not just
   cite an SDK by name." The repo's own precedent does this correctly:
   `docs/features/scan-sheet/spec.md:74-80` pastes the Go struct with its `json:"…"` tags. The only
   verbatim upstream quote in the whole feature is one Ukrainian sentence for `delete`
   (`spec.md:38`).
   **Resolution:** Fix now — paste the actual `AdditionalServiceGeneral` request/response schemas
   (official docs capture, or the two Go structs) into `spec.md` §1 / `api-sync-report.md`.

2. **[stage-1 · CONFIRMED, most severe] `ReturnAddressRef` mapping shipped with a self-declared
   open blocker** — `sad.md` §11 row 1 states verbatim that the `ReturnAddressOption.Ref` ↔
   `ReturnAddressRef` mapping "genuinely blocks `/sdd:api` … and `/sdd:review` cannot PASS with it
   still open (CLAUDE.md sourcing policy)." It is still open: `public-api.md` §10 item 1,
   `spec.md:351` (marked "this one blocks, not just tracks"), and `api-sync-report.md:88-95`
   resolves it as "Accept the design as-is, track as an open risk." `spec.md:351` records a
   *contrary* third-party source (`ReturnAddressRef` may expect a counterparty-address reference,
   not the return-address ref used) — a cross-source discrepancy, which CLAUDE.md says blocks ship
   outright, not merely tracks. The unverified assumption is hard-coded at
   `src/modules/additional-service/index.ts:241` (`ReturnAddressRef: options[0]!.Ref`) and shipped
   with only a README "open risk" note (`README.md:124-129`). AC-20 is implemented against an
   unverified wire contract.
   **Resolution:** Fix now — confirm against official Nova Poshta docs or a live test key before
   merge.

3. **[stage-1 · CONFIRMED] Three request fields ship with zero sources** — `updateReturn`/
   `updateRedirect`'s `Ref` field (`src/types/additional-service.ts:110,232`,
   `src/modules/additional-service/index.ts:155-160,198-203`), `CheckReturnEditPossiblePayload.Address`
   (`types.ts:33`), and `createRedirect.ServiceType` (`types.ts:213`) are all marked `low` in
   `api-sync-report.md:33` and admitted unconfirmed in `spec.md:70` ("neither cross-checked SDK
   exposed `update`'s own struct directly this session"). Under CLAUDE.md this is a sourcing-policy
   violation, not a tolerable open question — and since tests only mock-echo whatever the module
   sends (`additional-service.test.ts:360-374`), a wrong field name would not be caught.
   **Resolution:** Fix now — trace these three fields to official docs or 2 agreeing third-party
   sources.

4. **[stage-2 · CONFIRMED] Unchecked cast makes `CheckReturnEditPossibleResult.info` lie** —
   `src/modules/additional-service/index.ts:142` does `info: envelope.info as ReturnEditInfo`,
   while the client types it `info?: unknown` (`src/client.ts:29`) and
   `src/types/additional-service.ts:50` declares it non-optional. If Nova Poshta omits `info` on
   this response, callers get `undefined` behind a non-optional type and a raw `TypeError` — not
   the library's `NovaPoshtaApiError` — breaking CLAUDE.md's single-error contract. No test covers
   the info-absent case (`additional-service.test.ts:114-130` always supplies it), and this
   contradicts `sad.md` §4 decision 6's defensive-typing rule the module applies everywhere else.
   **Resolution:** Fix now — make `info?: ReturnEditInfo` optional and add a test for the
   omitted-`info` shape.

5. **[stage-2 · CONFIRMED, low] No changeset for the module** — `.changeset/` has one file per
   previously shipped module (`common-reference-lists.md`, `internet-document.md`,
   `tracking-document.md`, `scan-sheet.md`) but none for `additional-service`; the 19-method public
   surface added in `src/index.ts:138-176` would publish with no version bump.
   **Resolution:** Fix now — add `.changeset/additional-service.md` (minor), matching the pattern
   used by the other modules.
