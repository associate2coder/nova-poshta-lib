## Resolution

All 5 findings fixed directly in this session, per explicit instruction to resolve every open
finding without a further per-item negotiation pass:

- **F1:** `test/unit/build-surface.test.ts` now computes the newest mtime across every file under
  `src/` once at load time and fails loudly if a checked declaration file predates it, via a shared
  `readFreshDeclaration()` helper replacing all four ad hoc try/catch blocks. Verified the new check
  actually fires (`touch src/index.ts` → all 8 build-surface tests fail with the new stale message)
  before rebuilding and confirming green again.
- **F2:** added `SaveCallArgument`/`UpdateCallArgument` types derived from
  `Parameters<InternetDocumentModule["save"/"update"]>[0]`, plus two new test cases exercising the
  mixed-leg and missing-field `@ts-expect-error` cases against that call-site type rather than the
  named variants alone.
- **F3:** `sad.md` §9's ADR-0001 row now reads "Superseded by 0004", matching the ADR file.
- **F4:** `sad.md` flow 3 gained an `alt Documents is empty` branch showing the pre-fetch throw.
- **F5:** added `.changeset/internet-document.md` (minor), mirroring `common`'s existing changeset
  style.

**Also, per instruction, consulted Nova Poshta's official documentation before this pass** (see
`spec.md` §8 OQ-1's seventh-pass narrowing for the full account): `developers.novaposhta.ua` (the
portal named throughout this spec's drafting) still returns HTTP 403 to every automated fetch,
unchanged. A different official Nova Poshta domain, `devcenter.novaposhta.ua`, is reachable only via
a search engine's cached crawl (direct fetch fails on a broken TLS handshake) and its developer blog
independently confirms, from a primary source for the first time, two assumptions this spec
previously carried only as community-SDK-derived "unconfirmed"/"high confidence" items: the print
link's `apiKey` embedding (AC-13) and the single-combined-link-for-multiple-refs behavior (AC-11/
AC-12) — both already matched by the shipped implementation. `spec.md` §1/§6.1/§8, `contracts/
public-api.md` §3.7, and ADR-0003's Context section were updated to cite this. The remaining §8
sub-questions (exact required-field matrix per `ServiceType`, `delete`'s per-Ref response shape,
pagination `totalCount`, the print endpoint's 200-status blank-page failure signal) stayed open —
no reachable source gave a full field/parameter list for any of them.
